# Планировщики (Schedulers)

## Обзор

Система использует Spring Scheduler для автоматической загрузки данных в фоновом режиме. Все планировщики работают с оптимизированными сервисами, использующими параллельную обработку.

## Основные планировщики

### 1. CandleSchedulerService
**Расписание**: `0 10 1 * * *` (1:10 по московскому времени)
- **Функция**: `fetchAndStoreCandles()`
- **Описание**: Автоматически загружает минутные и дневные свечи за предыдущий день
- **Типы активов**: SHARES, FUTURES, INDICATIVES
- **Особенности**: 
  - Сначала загружает минутные свечи, затем дневные (с паузой 10 секунд)
  - Использует асинхронную загрузку через `saveMinuteCandlesAsync` и `saveDailyCandlesAsync`
  - Логирует начало и завершение в SystemLogEntity

### 2. MorningSessionScheduler
**Основное расписание**: `0 50 1 * * *` (1:50 по московскому времени)
- **Функция**: `fetchAndStoreMorningSessionPrices()`
- **Описание**: Загружает цены открытия утренней сессии за предыдущий день
- **Проверка выходных**: Пропускает выполнение, если предыдущий день был выходным
- **Дополнительные расписания**:
  - Выходные дни: `0 1 2 * * 0,6` (2:01) - `fetchAndStoreWeekendOpenPrices()` - загружает цены открытия за текущий день
  - Рабочие дни: 
    - `0 1 7 * * 1-5` (7:01) - `fetchAndStoreWorkdayOpenPrices7AM()` - загружает цены открытия за текущий день
    - `0 1 9 * * 1-5` (9:01) - `fetchAndStoreWorkdayOpenPrices9AM()` - загружает цены открытия за текущий день
    - `0 1 10 * * 1-5` (10:01) - `fetchAndStoreWorkdayOpenPrices10AM()` - загружает цены открытия за текущий день

### 3. EveningSessionSchedulerService
**Расписание**: `0 40 1 * * *` (1:40 по московскому времени)
- **Функция**: `fetchAndStoreEveningSessionPrices()`
- **Описание**: Загружает цены закрытия вечерней сессии за предыдущий день
- **Типы активов**: SHARES, FUTURES, INDICATIVES
- **Особенности**: 
  - Пропускает выполнение в выходные дни (вечерняя сессия не проводится)
  - Использует последнюю минутную свечу за день для определения цены закрытия

### 4. VolumeAggregationSchedulerService
**Расписание**: `0 0 2 * * *` (2:00 по московскому времени)
- **Функция**: `fullRefreshVolumeAggregation()`
- **Описание**: Обновляет материализованное представление агрегации объемов
- **Операция**: `REFRESH MATERIALIZED VIEW CONCURRENTLY invest.daily_volume_aggregation` (с fallback на обычное обновление)
- **Особенности**: Пытается использовать CONCURRENTLY для обновления без блокировки, при ошибке использует обычное обновление

### 5. ClosePriceSchedulerService
**Расписание**: `0 0 1 * * *` (1:00 по московскому времени)
- **Функция**: `fetchAndStoreClosePrices()`
- **Описание**: Загружает цены закрытия за предыдущий день
- **Типы активов**: SHARES, FUTURES (только RUB инструменты, исключая indicatives)

### 6. LastTradesService
**Расписание**: `0 0 3 * * *` (3:00 по московскому времени)
- **Функция**: `fetchAndStoreLastTrades()`
- **Описание**: Загружает обезличенные сделки за предыдущий день
- **Типы активов**: SHARES, FUTURES
- **Особенности**: Торги проводятся в выходные дни, поэтому проверка выходных дней отключена
- **Примечание**: LastTradesSchedulerService временно отключен (закомментирован)

### 7. InstrumentPreloadSchedulerService
**Расписание**: `0 45 0 * * *` (0:45 по московскому времени)
- **Функция**: `preloadAndPersistInstruments()`
- **Описание**: Предзагружает список инструментов в кэш и асинхронно сохраняет в БД
- **Типы активов**: 
  - SHARES (только биржа moex_mrng_evng_e_wknd_dlr)
  - FUTURES (все)
  - INDICATIVES (все)
- **Особенности**: 
  - Прогрев кэша выполняется синхронно
  - Сохранение в БД выполняется асинхронно с параллельной обработкой
  - Использует отдельные taskId для каждого типа инструментов

### 8. AssetFundamentalsSchedulerService
**Расписание**: `0 0 3 * * *` (3:00 по московскому времени)
- **Функция**: `updateAssetFundamentals()`
- **Описание**: Автоматически обновляет фундаментальные показатели всех акций
- **Особенности**: 
  - Использует батчинг по 100 активов
  - Принудительное обновление существующих записей
  - Логирует начало и завершение в SystemLogEntity

### 9. DividendSchedulerService
**Расписание**: `0 50 0 * * *` (0:50 по московскому времени)
- **Функция**: `fetchAndStoreDividends()`
- **Описание**: Загружает дивиденды по всем акциям за период 2024-01-01 по 2026-12-31
- **Типы активов**: SHARES
- **Особенности**: 
  - Логирует результат в SystemLogEntity с детальной статистикой
  - Обрабатывает ошибки с сохранением в системный лог

## Временно отключенные планировщики

### LastTradesSchedulerService
**Статус**: Временно отключен (закомментирован)
- **Было расписание**: `0 0,30 2-23 * * *` (каждые 30 минут с 2:00 до 00:00)
- **Функция**: `scheduledLastTradesLoading()`
- **Описание**: Загружал обезличенные сделки каждые 30 минут в течение дня
- **Примечание**: Функциональность заменена на ежедневную загрузку через LastTradesService в 3:00

## Технические особенности

### Используемые сервисы
- **MinuteCandleService** - для загрузки минутных свечей
- **DailyCandleService** - для загрузки дневных свечей
- **MorningSessionService** - для загрузки цен открытия утренней сессии
- **MainSessionPriceService** - для загрузки цен закрытия основной сессии
- **LastTradesService** - для загрузки обезличенных сделок
- **InstrumentService** - для работы с инструментами (акции, фьючерсы, индикативы)
- **DividendService** - для загрузки дивидендов
- **AssetFundamentalService** - для обновления фундаментальных показателей
- **CachedInstrumentService** - для работы с кэшированными инструментами

### Логирование
Все операции планировщиков логируются в консоль:
- Начало и завершение операций
- Время выполнения
- Статус выполнения
- Детальная информация о процессе
- Уникальные taskId для отслеживания

### Обработка ошибок
Каждый планировщик включает комплексную обработку ошибок:
- Логирование всех исключений
- Продолжение работы при ошибках в отдельных операциях
- Детальная информация об ошибках в логах
- Graceful degradation при проблемах с внешними сервисами

### Проверка выходных дней
Планировщики по-разному обрабатывают выходные дни:
- **EveningSessionSchedulerService** - пропускает выполнение в выходные дни (вечерняя сессия не проводится)
- **MorningSessionScheduler** - имеет отдельные расписания для выходных (2:01) и рабочих дней (7:01, 9:01, 10:01)
- **LastTradesService** - не проверяет выходные дни, так как торги проводятся и в выходные
- **CandleSchedulerService** - обрабатывает все дни без проверки выходных

## Мониторинг

Для мониторинга работы планировщиков используйте логи приложения:

```bash
# Поиск по taskId
grep "MORNING_" logs/application.log
grep "DIVIDEND_" logs/application.log

# Статистика выполнения
grep "=== ЗАВЕРШЕНИЕ" logs/application.log

# Ошибки планировщиков
grep "Критическая ошибка" logs/application.log
```

## Настройка расписания

Для изменения расписания отредактируйте аннотацию `@Scheduled`:

```java
// Примеры расписаний:
@Scheduled(cron = "0 0 2 * * *", zone = "Europe/Moscow")  // Каждый день в 2:00
@Scheduled(cron = "0 1 7 * * 1-5", zone = "Europe/Moscow") // Рабочие дни в 7:01
@Scheduled(cron = "0 1 2 * * 0,6", zone = "Europe/Moscow") // Выходные в 2:01
```

## API для ручного управления

### VolumeAggregationController
- `POST /api/volume-aggregation/refresh` - ручное обновление агрегации объемов

### SystemController
- `GET /api/system/health` - проверка здоровья системы
- `GET /api/system/diagnostics` - диагностика системы
- `GET /api/system/stats` - статистика системы
